# 側邊欄項目會出現在哪裡

[English](compatibility.md)

CustomerFD 的根節點（例如「開發」）是一個註冊在目前使用者底下的 Shell Namespace Extension。Windows 裡只要是透過殼層命名空間顯示資料夾的地方，都可能列出它；但每個地方的條件不同。下表是盤點結果與每項的處理方式。

## 支援

| 位置 | 條件與說明 |
|---|---|
| 檔案總管左側邊欄 | 主要用途。需要 `System.IsPinnedToNameSpaceTree=1`（控制中心「在側邊欄顯示」）。 |
| 64 位元程式的「開啟」「另存新檔」「選擇資料夾」視窗 | 0.3.3 起。新式檔案視窗（Common Item Dialog，以及新式 `GetOpenFileName`／`GetSaveFileName`）只在側邊欄列出標示為「含有檔案系統資料夾」的項目，因此根節點與對應資料夾帶有 `SFGAO_FILESYSANCESTOR`／`SFGAO_STORAGEANCESTOR`（登錄 `ShellFolder\Attributes = 0xB8800000`）。Microsoft Store／WinUI 程式的檔案選擇器在 64 位元的代理程序裡執行，也屬於這一類。 |
| 32 位元程式的同樣視窗 | 0.3.3 起。32 位元程式讀的是 `HKCU\Software\Classes\WOW6432Node\CLSID`，而且只能載入 32 位元 DLL：安裝程式另外安裝 `x86\cfd_shell.dll` 並註冊到 WOW6432Node。控制中心「關於 › 安裝資訊」與 `CustomerFD-Setup.exe --check` 會檢查這項註冊。 |
| 以系統管理員身分執行的程式 | 同一個帳號提權時讀的是同一份 HKCU，可以看到。 |
| 舊式「瀏覽資料夾」樹狀視窗（`SHBrowseForFolder`） | 根節點出現在「桌面」底下。程式要求「只能選檔案系統資料夾」時，根節點本身不能選，底下的資料夾可以。 |

## 使用上的限制

| 情況 | 說明 |
|---|---|
| 根節點本身不是真實路徑 | 根節點是虛擬資料夾：不能直接存檔在根節點那一層、不能把它當成資料夾選取，「複製路徑」或「在終端機開啟」在根節點上也沒有路徑。進到底下任一資料夾後，都是真實的檔案系統路徑，一切正常。 |
| 「從桌面隱藏」 | 只影響桌面圖示；開啟的話，部分程式的樹狀選擇視窗也可能跟著不顯示。 |
| 位置列 icon | 第一層資料夾的位置列 icon 會維持上一個位置，見 README 的已知問題。 |

## 不支援（設計上無法處理）

| 情況 | 原因 |
|---|---|
| 另一個帳號（包括提權時輸入另一個管理員帳號） | CustomerFD 只安裝給目前帳號（HKCU）。另一個帳號要自己安裝一次。 |
| 自己畫檔案視窗的程式（Java Swing、非原生的 Qt／GTK、部分遊戲與工具） | 它們不使用 Windows 殼層命名空間，看不到任何殼層擴充套件的項目（OneDrive、Dropbox 也一樣）。 |
| 非常舊的 Windows 3.1 樣式檔案視窗 | 根本沒有側邊欄。 |
| ARM64 版 Windows | 檔案總管是 ARM64 程序，無法載入 x64 擴充套件；安裝程式會擋下。 |
| 沒有檔案總管殼層的環境（RemoteApp、Server Core、替代殼層） | 沒有側邊欄可以顯示；安裝程式會提示。 |

## 檢查方式

- `CustomerFD-Setup.exe --check`：檢查執行環境，並對已安裝的版本做自我測試（包含 64 與 32 位元註冊）。
- 實測：用記事本（64 位元）以及任一 32 位元程式各開一次「開啟」與「另存新檔」視窗。在工作管理員的「詳細資料」頁加上「平台」欄可以看出程式是 32 還是 64 位元。
